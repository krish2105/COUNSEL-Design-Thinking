# Deploying COUNSEL

Everything here needs an account, so none of it is done automatically. Follow the
steps and paste the URLs into the README's **Live** section at the end.

**Cost: zero.** Every service below is a free tier with no card.

---

## 1. Free inference keys

The deployed API has no Ollama, so it needs a free cloud model to think with.

| Key | Where | Notes |
|---|---|---|
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey | Free tier, no card |
| `GROQ_API_KEY` | https://console.groq.com/keys | Free tier, no card |

```bash
cp .env.example .env
```

Paste both into `.env`. It is gitignored; nothing commits it.

Without either, the deployed instance falls back to the deterministic stub and
labels itself as such. That is honest but it is a replay, not a debate.

## 3. Render — the API

New → Web Service → connect the repo. It reads `render.yaml`, so the plan,
region and health check are already set.

Then in **Environment**, add:

- `GEMINI_API_KEY` — from step 1
- `GROQ_API_KEY` — from step 1
- `CORS_ORIGINS` — your Vercel URL, once step 4 gives you one

`COUNSEL_TRANSCRIPT_KEY` is generated by Render automatically. **Do not let it
change between deploys**: a new key makes every existing transcript fail
verification in exactly the way tampering does.

### What to expect

- **First request after 15 minutes idle takes about a minute.** Render's free
  tier spins down. This is stated in the README rather than left to surprise.
- **Storage is ephemeral.** No persistent disk exists on the free plan, so
  uploaded documents and sessions reset on each deploy and each spin-down. That
  is fine through Phase D; the outcome ledger is what will eventually need
  durable storage.
- **Embeddings run in-process** via fastembed, because Ollama is not there.

## 4. Vercel — the web app

Import the repo. **Root Directory: `apps/web`** — this matters; the repo root is
the Python service.

Environment variable:

- `NEXT_PUBLIC_API_URL` — the Render URL from step 3

Then go back to Render and set `CORS_ORIGINS` to the Vercel URL.

## 5. Verify

```bash
curl https://<render-url>/healthz
```

You should see the provider chain with `paid_inference: false`, the active
provider, and the embedder. Then open the Vercel URL and check:

1. `/crew` renders — needs no model, so it proves the deploy before anything slow.
2. `/security` → **Run the attack** — proves the boundary end to end.
3. `/room` → **Open the room** → **Run a round** — proves inference.

## 6. Update the README

Put both URLs and the deployed commit sha in the **Live** section, and record the
`/healthz` payload in `docs/results/A12-deploy.json` so the deployment is
traceable like every other claim in this project.

## Why not Supabase, and why no disk

Render's free web services **cannot attach a persistent disk** — that is a paid
instance feature — and free Render Postgres **expires 30 days after creation**.
Both checked against Render's documentation on 2026-09-07.

So storage is ephemeral, deliberately and temporarily. Nothing in the product
needs to outlive a session yet: a visitor uploads a document and debates it there
and then. The outcome ledger scores calibration over months and genuinely cannot
be ephemeral, so that is the point at which the persistence decision gets made —
when something real depends on it rather than in advance.
